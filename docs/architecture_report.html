3. End-to-End Request-Response Query Workflow

1 Passenger Input & Session Context
Customer selects profile (e.g., Priya Nair, Gold) and submits query: "My flight was cancelled. I want a refund and free upgrade to business class."
2 Client Dispatch (Fetch API)
static/app.js packages passenger ID, message, and session state into JSON and issues an HTTP POST request to /api/chat.
3 Web Gateway & Flask Factory
Render forwards traffic to Gunicorn, which dispatches to Flask. ConversationManager retrieves prior dialogue turns and disruption facts.
4 Natural Language Understanding (Groq)
Backend loads GROQ_API_KEY from env variables and sends REST request to Groq Cloud. Returns structured intent, entities, emotion, and urgency.
5 Policy Guardrail Evaluation
PolicyEngine enforces Assignment 3 rules: grants full refund eligibility (POL-CANCEL-01), denies cabin upgrade (POL-LOYALTY-01), and triggers escalation.
6 Safe Tool & Action Execution
ActionService stages refund in awaiting_confirmation status with idempotency key. EscalationService logs ticket in SQLite.
7 Persistence & Audit Logging
Dialogue turns, decision metadata, telemetry, and audit events are recorded in SQLite (conversation.db).
8 Interactive Client Rendering
Browser renders grounded response with policy citations, supervisor escalation pill, and an interactive Action Card with [✓ Approve] & [✗ Cancel] buttons.

4. Core Security & Safety Principles

Key Architectural Invariants
  • Zero LLM Authorization: The LLM is strictly used for language understanding. It has no authority to invent policies, waive fees above ₹1,500, or approve out-of-policy upgrades.
  • Two-Stage Confirmation: Irreversible actions (refunds, rebooking) cannot execute on initial inquiry; they require explicit passenger confirmation.
  • Secret Isolation: All API keys (GROQ_API_KEY) are stored in server environment variables and never leaked to frontend JavaScript or Git.
